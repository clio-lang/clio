# Checked native call fast paths

The [bottleneck investigation](../../benchmarks/results/bottlenecks-2026-10-24.md) identified repeated call admission as the main cost in recursive source benchmarks. The implementation retains logical call depth, stack reserve, cancellation, fault priority and balanced unwinding. Source functions retain their existing noinline boundaries and conservative stack admission.

Generated LLVM has small internal, always-inline implementations of enter/leave/poll. `InvocationABI` derives field offsets from the actual standard-layout runtime type; compiler and runtime use the same pinned host ABI. Pointer width and atomic-bool representation are statically checked. The new slow-poll symbol also makes an old runtime fail linkage rather than silently supplying an incompatible fast-path implementation.

Poll mode zero means no token, observer, fault or settlement has been bound. Mode one checks a non-null cancellation token with an acquire atomic load. Binding a poll observer, faulting or settling permanently selects mode two, which calls the existing runtime poll implementation. Binding or removing a token cannot clear an existing observed/faulted/settled state. Poll counters and settled-context faults preserve their existing behavior; cancellation is not disabled to improve benchmark results.

macOS stack bounds are immutable metadata cached in trivial C TLS for the executing physical pthread. C TLS is used because Darwin C++ `thread_local` exposes storage through a C++ accessor ABI. A fresh/reused pthread receives zero-initialized storage; first use queries its real stack and reserves the same 128 KiB headroom. Alternate stacks remain outside the admitted pthread stack.

A generated native call chain acquires those bounds once, then checks its actual stack pointer at every admitted call. Native frames cannot migrate while that synchronous chain remains live. Every generated return, including fault/cancellation exits, releases its logical call slot. The chain lease clears at its own entry depth, which may be nonzero because a host runtime admission already exists. A continuation can migrate only after its native frames return; its next chain reacquires the executing pthread's bounds. No TLS pointer is retained in an invocation across migration.

`native-fast-calls` checks repeated success, probe counters, preserved faults, settled contexts, immediate and asynchronous token cancellation, depth exhaustion and complete unwinding in debug, optimized, ASan/UBSan and TSan variants. macOS cases reuse one invocation across differently sized worker stacks while a manual admission remains active, return it to the main thread, and reject entry near the stack reserve. The numerical suites independently check cancellation and cleanup in packed matrix operations.

See the [optimization results](../../benchmarks/results/optimization-2026-10-24.md) for fair source and numerical timings, including a separate control with a bound cancellation token. Diagnostic guard-removal results are not production performance claims.

## Scalar tail recursion

Direct scalar self calls qualify only when their result is returned unchanged through PHIs/unconditional branches. Pointer/aggregate arguments, frame-local allocas, non-tail work, large signatures and bodies near the stack budget retain their existing lowering. The transformation has bounded call-site/return counts and reserves 8 KiB of the existing 16 KiB instruction budget before adding its state; the final body is checked again. The external source-function boundary retains `noinline`.

Eligible calls reuse their physical frame while retaining the 128-slot logical depth limit. Parameter PHIs implement simultaneous argument replacement. Every admitted tail step acquires a logical slot; every return releases it. Observed execution, and bodies that may call helpers, retain ordinary admission. Every token-bound logical return still performs its leave/post-call poll, including faults, cancellation and rejected child entry. This preserves probe counts and priority of existing faults. Unbound, unobserved, fault-free return polls are proven clear and can release their slots together; the chain's stack lease clears only if that range actually contains its owning depth.

A further proof applies only to scalar bodies without memory, callbacks, non-tail calls or side-effecting intrinsics. Without an observer, the only possible asynchronous input is an optional cancellation token; other invocation fields remain exclusive to the executing owner. Such a body keeps its logical depth in SSA, tests the same 128-slot limit on every recursive step, and publishes that depth before unwinding. A bound token is loaded with acquire ordering before every recursive depth check, matching ordinary admission order. Denied cancellation acquires no slot and follows the existing post-call poll/unwind. Its own terminal fault still uses the checked failure path. Observed invocations use the ordinary path, and token-bound return polls remain explicit. This is not unlimited tail recursion or a cancellation bypass.

Native stack reserve and outer entry checks remain in place. A reused frame has no dynamic allocas and does not grow with tail iteration, so the transformation can reduce physical stack consumption without increasing the logical limit. Exact physical resource-failure thresholds are not a language promise; stack admission continues to use the executing thread's bounds. The existing lease is released before migration.

`native-tail-calls` and `native-tail-calls-software` check hardware and software policies in debug, optimized, ASan/UBSan and TSan modes. Differential qualification against the frozen pre-change compiler compares exact results, status/location, observed poll counts and final logical depth, including preexisting host admissions, depth exhaustion, helper-call fallbacks, faulted/settled contexts, asynchronous cancellation, worker migration, small stacks, signed zero and NaN payloads. Independent integer and bit-level references and eligibility controls remain runnable without the frozen compiler.

## Total hardware casts

All supported integer types have at most 64 bits. Every value fits within the finite range of float32 and float64, so integer-to-float conversion never needs an overflow admission calculation. Float32-to-float64 is also total. Hardware mode now emits these casts with a constant true admission result, retaining the actual hardware rounding operation. Float narrowing, float-to-integer and integer-to-integer checks remain unchanged; explicit software mode still uses its existing exact conversion implementation.

`native-total-hardware-casts` checks all 17 total conversion pairs against APFloat in four build modes. Every 8-bit and 16-bit input is covered exhaustively; larger widths include power/tie boundaries and deterministic random patterns. Float widening includes subnormals, signed zeros, infinities and NaNs (payload preservation remains outside the hardware conversion contract). These checks use the default round-to-nearest environment; software conversion qualification continues to cover eight floating environments independently.

The full tail admission path sits in an internal `noinline` ABI helper. This prevents LLVM loop motion from speculating Darwin's TLS address resolver into the unbound scalar loop. The helper performs the same poll/depth/native-stack admission and acquires exactly one logical slot; its own physical frame does not create another source call. [Machine-frame qualification](../../benchmarks/results/tail-call-stack-audit-2026-10-24.json) checks both it and GCD in all four build modes and both arithmetic policies: the audited frames remain below the existing 16 KiB function budget and 128 KiB reserve.

Hardware tensor-cast controls additionally cover ranks zero through three, immutable strided inputs, retained output leases, invalid metadata, injected allocation failure, and immediate/active cancellation. The independent APFloat checks qualify vectorized loop output as well as scalar casts; removing a proven-clear range check does not remove loop cancellation or ownership handling.

The compiler tries LLVM loop specialization on a private clone of a proven scalar tail body. Loop simplification, LCSSA and nontrivial unswitching move the invocation-mode/token choices outside the recursive loop. The specialized candidate replaces the original body only if it still fits the same 16 KiB conservative stack budget; otherwise it is discarded and the previously checked body remains. Source function identity, signature and linkage are preserved. This limits code growth and keeps source acceptance unchanged when specialization is too large.

The [final tail-call results and qualification](../../benchmarks/results/tail-calls-2026-10-24.md) include all source comparisons, token-bound controls, intermediate measurements and residual performance gaps. The current audited maximum for GCD and its admission shim is 464 bytes across the checked build/policy variants.

## Budgeted checked-call inlining

After admission, return and post-call polls are installed, the compiler freezes the eligible source bodies and tries one level of direct-call inlining on private clones. Candidates have scalar arguments/results, at most eight source arguments, no frame allocations or loops, and at most 250 original instructions. At most four original call sites are expanded per caller. Frozen bodies make the expansion independent of module order and prevent repeated recursive growth. Tail-loop bodies and aggregate signatures retain their existing lowering.

Inlining copies each callee's complete checked body. Logical entry, depth exhaustion, fault branches, return balancing and post-call polls remain present; this does not skip a logical call because its physical frame disappeared. Existing function identities remain available for indirect references. The combined candidate replaces the original only after simplification and the unchanged 16 KiB stack-budget check. An oversized candidate is discarded without rejecting previously accepted source. The adopted source functions still carry `noinline` for downstream LLVM optimization, preventing further uncontrolled expansion. Physical stack consumption may decrease, while logical depth remains limited to 128.

`native-checked-inlining` checks retained admissions/polls, one-level recursive growth, module order and budget fallback. The two `native-checked-inlining-source-*` tests check hardware/software floating recursion against independent references, including signed zero, subnormals, infinities/NaNs, conversion/division faults, preexisting host admissions, observed polls, cancellation and settled contexts in debug, optimized and sanitizer modes. Optional `--baseline` qualification compares result bits, fault locations, poll counts and final depth against the pre-inlining compiler. The existing tail/fast-call suites additionally cover asynchronous cancellation, migration and bounded native stacks.

Static tensor-to-buffer extraction now preserves the tensor's actual shape while keeping dynamic stride metadata. A dynamic buffer shape does not match a statically shaped tensor under MLIR's verifier. `native-static-numerical-shapes` covers static matrix products, fused reductions, empty vectors and packed matrix execution for float32/float64 in all build modes; downloaded Linux/Windows package acceptance also includes static matrix/reduction controls.

The [inlining results and qualification](../../benchmarks/results/checked-inlining-2026-10-24.md) retain interleaved baseline/current controls, fresh source comparisons, all differential records and 160 machine-frame audits (maximum 832 bytes on this Mac).
