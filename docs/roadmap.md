# Roadmap

## Native implementation status

The native rewrite is a working CPU/Apple GPU compute subset, not yet the full accepted language. The released JavaScript prototype is separate. The implementation record below includes historical intermediate states; this table summarizes the current position.

| Area | Current position | Remaining scope |
| --- | --- | --- |
| Toolchain, handwritten frontend and typed IR | Implemented for the native subset | Broader syntax/value forms and diagnostics |
| Immutable tensor memory and CPU computation | Implemented with checked ownership, shapes and strict float32 arithmetic | Additional element types, general values and broader operations |
| Structured local execution | Bounded multi-worker tasks, waits, recovery, cancellation and settlement implemented | Broader asynchronous function composition |
| Apple GPU execution | Mixed CPU/GPU programs, explicit transfers, rank-one/rank-two kernels and strict arithmetic implemented | Wider kernels/types, capability breadth and further performance work |
| Shared execution planning | CPU and Metal emitters now consume the [common continuation planner](design/continuations.md) | Resumable mixed helper bodies and further backend integration |
| Native language and developer experience | Development compiler command available | Modules/libraries, broader control/data constructs, editor tooling and distribution qualification |
| Native distributed execution | Pending the agreed design review | Contracts, transport, deployment, failure/cancellation and remote storage lifetimes |
| Additional GPU targets | Apple first | NVIDIA/Windows follows Apple qualification |

Next: resumable helper bodies in mixed CPU/GPU programs. Broader language/type support and native tooling follow their own design and qualification gates. Discuss distributed execution before implementing it. Prototype release completion does not count as native implementation coverage.

## Native implementation record

**Design and implementation record:** treat Kalandra 0.13 as the released prototype and design a fresh immutable, memory-safe language for native CPU, GPU, and distributed execution. The [core syntax and immutable value behavior](design/core.md) are accepted as the starting point, with explicit numeric families replacing `Number`. The [memory design](design/memory.md) selects automatic lifetimes and compiler-chosen allocation without an allocation-scope keyword. The [numeric types and arithmetic rules](design/numbers.md) are accepted. The [errors and effects direction](design/errors.md) is accepted. [Resources and task lifetimes](design/execution.md) are accepted, including inline spawn/await. [Variants and error payloads](design/variants.md) are accepted. [Tensor types and shapes](design/tensors.md) are accepted. [Placement, transfers, and bulk tasks](design/placement.md) are accepted in direction. The [complete CPU/GPU/remote application example](design/compute-example.md) is accepted as the integration direction. The [first native CPU compiler milestone](design/cpu-milestone.md) is accepted as the implementation sequence. Its [pinned MLIR/LLVM toolchain proof](../native/toolchain-proof/README.md) passes on macOS ARM64; the [handwritten C++23 lexer/parser](design/frontend.md) now parses the projection fixture with diagnostics and sanitizer-tested limits. [Name resolution and typed IR](design/semantics.md) now check the projection fixture with literal typing, symbol resolution, shape facts/guards, and strict numeric metadata. [Native MLIR/LLVM lowering](design/native-codegen.md) now compiles the source into a standalone executable producing 163. The first sequential float32 CPU milestone and conformance sweep now pass, including 1,029 runtime shape/content cases per build variant, nested/shared tensor lifetimes, allocation-failure cleanup, evaluation order, and a fresh source-only build. The [native local-task contract](design/native-tasks.md) now specifies ownership, explicit status propagation, resumable waits, bounded scheduling, and failure/cancellation settlement. Checked invocation contexts and managed tensor ownership now replace process-global cleanup on source-generated paths; isolated checked faults preserve sibling/parent data and allow another invocation to continue. The single-worker task core now implements resumable waits, bounded admission, cached immutable outcomes, and group cancellation/settlement using synthetic native entries. The first source task subset now lowers parallel/spawn/await and TaskError propagation to native LLVM continuations, retaining the MLIR tensor kernels. Native TaskError recovery now implements catch, exhaustive built-in matching, typed fields, and handler-local try/fail propagation. Bounded multi-worker CPU execution and cooperative loop cancellation now pass their conformance tests. The native conformance suites pass, including debug, optimized, ASan/UBSan, and separate TSan coverage of runtime and generated code. The [native CPU scaling baseline](../benchmarks/results/native-cpu-2026-10-15.md) now measures warmed kernel throughput, scheduling overhead, and allocation counts. Matrix reduction scratch reuse now passes the same numerical, failure, and cancellation gates, with [before/after measurements](../benchmarks/results/native-cpu-2026-10-15-scratch.md). The [scheduler profile](../benchmarks/results/native-scheduler-2026-10-15.md) now separates table-capacity costs from multi-worker coordination, using uninstrumented phase timings and separate diagnostic probes. Unnecessary idle-worker notifications and empty-drain activation are now removed, with [before/after measurements](../benchmarks/results/native-scheduler-2026-10-15-wakeups.md), held-lease wakeup regressions, and unchanged numerical conformance. Worker/controller wait channels are now separated, with targeted active notifications and [paired measurements](../benchmarks/results/native-scheduler-2026-10-15-targeted.md). Ready-table sweeps are now replaced with [bounded runnable tracking](../benchmarks/results/native-scheduler-2026-10-15-runnable.md), retaining narrow-queue nested spawning and deferred continuation progress. Maintenance now uses [bounded occupancy indexes](../benchmarks/results/native-scheduler-2026-10-15-maintenance.md) for unfinished tasks and live records/groups, preserving sparse high slots, deep nested waits, and concurrent cleanup. The [task-maintenance fast path](../benchmarks/results/native-scheduler-2026-10-15-dense.md) now skips primary task scans when no waiter or settlement exists, preserving group progress and cleanup leases. The [four-column SIMD comparison](../benchmarks/results/native-cpu-2026-10-15-simd.md) now records the first CPU microtile optimization, with separately rounded lane arithmetic, scalar tails, 1,617 aggregate cases, and 705 per-cell/shared cases. The [37-shape comparison](../benchmarks/results/native-shapes-2026-10-15.md) identified narrow-column and tail costs. Narrow dispatch and two-lane output/tail specialization are now implemented, with [paired shape measurements](../benchmarks/results/native-shapes-2026-10-15-pairs.md), 717 per-cell/shared cases, and extended cancellation/deadline coverage. The [cache-layout evaluation](../benchmarks/results/native-cache-2026-10-15.md) now measures strict C++ row/column and contraction-block prototypes against generated code and a library reference. The [MLIR 4×16/K256 port](../benchmarks/results/native-mlir-blocking-2026-10-15.md) now implements full/edge tiles in a private kernel, preserving narrow paths, checked storage and per-lane arithmetic, with 3,727 per-cell/shared cases, 506 actual allocation-payload cases, and renewed concurrency/cancellation/sanitizer checks. The optional [Apple GPU toolchain proof](../native/metal-proof/README.md) now executes handwritten MLIR GPU kernels through SPIR-V/SPIRV-Cross/Metal on an M2 Max. Finite, tail, and immutable-input checks pass, but IEEE edge probes expose subnormal and bridge signed-zero differences; strict float32 GPU admission remains unavailable. The [Apple GPU backend contract](design/apple-gpu.md) scopes device/storage tasks, completion, cancellation, numerical compatibility, and subsequent source lowering. The optional [native Metal transfer runtime](../native/metal/README.md) now adds managed host/device backings, checked uploads/downloads, nested transfer tasks, and scheduler external-completion leases with cancellation-safe cleanup, byte/command budgets, and failure injection. Host ASan/UBSan and separate TSan coverage exercise the bridge and scheduler. A [strict binary32 integer MLIR lowering](design/strict-gpu-float32.md) now verifies scalar float32 add/multiply and their separately rounded composition against APFloat and CPU hardware on CPU LLVM and Metal, with IEEE edge/stratified/random conformance and artifact/rejection checks. Direct hardware float32 remains incompatible; managed compute-task integration now passes through a checked private dynamic-array kernel ABI, including nested tasks, explicit transfers, IEEE differential conformance, cancellation, budgets, and failure cleanup. An optional source compiler now lowers a bounded rank-one float32 placement/transfer program into C++ supervisor continuations and source-generated strict GPU MLIR, with a standalone executable/shader build driver, transitive helper/constant checks, repeated calls, source diagnostics, and cancellation/failure conformance. The common compiler now selects the linked Metal backend with `--target metal`; retained CPU allocation leases and checked MLIR descriptor import/export pass CPU→GPU→compiled-CPU conformance. Common mixed-source typed IR, richer dynamic entry parameters, other arithmetic, general tensor kernels, and performance qualification remain gated. NVIDIA/CUDA on Windows follows Apple support. The native build uses CMake/Ninja/CTest with direct LLVM/MLIR C++ integration and no Bun/Node requirement. The original hand-written IR proof remains a separate backend reference; the source compiler has its own executable conformance tests. Concrete residency, deployment, and runtime API contracts remain tracked before their implementation. These documents describe the fresh design; their syntax is not implemented in the released compiler. Ordinary CPU and GPU functions now coexist in one source program: checked MLIR/LLVM CPU calls can consume explicit downloads, with float32 scalar results, allocation-failure cleanup, and separate sanitizer variants. CPU tensor results now retain immutable backing across CPU calls and GPU transfers; runtime guards check shapes that are unknown statically. Shared CPU/GPU helper compilation now preserves original tensor/scalar types in one checked function IR, with elementwise CPU loops, GPU lane lowering, propagated shape constraints, and differential numerical conformance. A common placement-aware task/residency IR remains subsequent work. Elementwise GPU entries now use signature-sized owned captures and compact reflected bindings for contributing rank-one/rank-two float32 tensors; unused arguments retain their logical contracts without consuming input bindings. See [entry parameter scope](design/apple-gpu.md#unused-tensor-arguments-and-shape-obligations).

Native GPU follow-up: [GPU-ABI-001](design/apple-gpu.md#tracked-follow-up-general-gpu-parameter-layouts-gpu-abi-001) now has [signature-sized owned captures](design/apple-gpu.md#signature-sized-gpu-captures), replacing the fixed two-tensor/eight-scalar storage. Broader types and tensor operations remain open. Backend resource limits are not language parameter limits. The first [rank-one GPU reduction](design/apple-gpu.md#rank-one-gpu-reductions) now implements `reduceSum` with scalar task results, the accepted deterministic tree and four-byte readback. The first [rank-two GPU matmul](design/apple-gpu.md#rank-two-gpu-matrix-multiplication) now preserves separately rounded products and the fixed tree, with matrix support in the mixed CPU/GPU source bridge. The [initial CPU/Metal performance baseline](../benchmarks/results/native-gpu-2026-10-15.md) now separates device command, resident task and transfer costs. The [strict normalization optimization](../benchmarks/results/native-gpu-2026-10-15-normalization.md) now removes per-bit integer loops, improving 256-square GPU command latency by 3.09× while preserving strict rounding and the accepted tensor tree. CPU still wins on tested matmul shapes. The [GPU tiling study](../benchmarks/results/native-gpu-2026-10-15-tiling.md) now qualifies cooperative/register candidates and shows shape-dependent benefits and regressions. The [49-shape crossover and managed selection](../benchmarks/results/native-gpu-2026-10-15-selection.md) now enable conservative two-row/quad dispatch on Apple M2 Max, preserving scalar GPU execution outside the measured profile and on other devices. Numerical, failure/lifetime and repeated resident/transfer measurements qualify the integration. [Reduction scratch reuse](../benchmarks/results/native-gpu-2026-10-15-reduction-reuse.md) now retains two alternating outputs while preserving the fixed tree and invocation isolation. [Rank-two GPU reductions](design/apple-gpu.md#rank-two-gpu-reductions) now keep matmul → reduceSum intermediates resident, returning only the final scalar with the same strict row-major tree. [Rank-two elementwise GPU helpers](design/apple-gpu.md#rank-two-gpu-elementwise-helpers) now support strict scaling/addition and transitive helpers with complete axis guards, enabling a resident matmul → adjust → reduceSum pipeline. [Serial reduction dispatch batching](../benchmarks/results/native-gpu-2026-10-16-reduction-batching.md) now uses one compute encoder for all levels with unchanged strict arithmetic, memory and lifecycle guarantees; warm timings are roughly flat. Apple-family reduction count words now share one immutable parameter buffer, cutting temporary Metal buffer objects from 23 to 4 for a million-element sum without changing requested payload bytes; [matched warm measurements](../benchmarks/results/native-gpu-2026-10-16-reduction-parameters.md) record lower managed-call latency on M2 Max. Strict tensor subtraction and scalar negation now share the CPU/GPU lowering, with [APFloat, lifecycle and source checks](design/apple-gpu.md#strict-tensor-subtraction-and-scalar-negation). [Inline CPU expressions](design/apple-gpu.md#inline-cpu-expressions-in-mixed-programs) now compose arithmetic, reductions and matmul directly in mixed-program main, through shared checked CPU kernels. 1. **Syntax baseline — implemented:** Port committed Clio syntax to Chevrotain and an independent AST. All 177 positive reference fixtures parse; syntax failures and AST shapes are tested. See [coverage and limits](compiler-port.md). Keep unfinished Clio changes separate.
2. **Compiler path — decorators, local modules, and JavaScript interop implemented:** Single-file resolution and gradual type checking now cover the original type errors, scopes, annotations, imports supplied by the host, and async/parallel metadata. Typed IR and Babel ESM emission now emit 146 of the 177 positive fixture forms, with differential behavior tests and source-map checks under Bun. The local project builder resolves relative/root imports, installed Kalandra packages with manifests, and explicit ESM/CommonJS packages, shares export signatures and runtime helpers, and emits native ESM. CLI build/run discover the nearest enclosing `kalandra.toml` and use its `build.source`, with standalone-file fallback and explicit output destinations. The language server shares manifest discovery, supports unsaved configuration changes, and isolates nested projects during source discovery. Indexed writes now preserve historical bracket lookup, read-back, and evaluation order, including chained targets. Direct self-tail calls in synchronous and async functions, including decorated functions, now run with bounded stack usage and preserve per-invocation closure bindings and explicit await points; explicitly awaited self-calls remain ordinary calls. Arithmetic operands, property-access bases, and supported call targets now lift bindings ahead of their statement, preserving binding order and enclosing-scope visibility. Unresolved semantics and preserved quirks are tracked in the [language design backlog](language-design-backlog.md). Next, expand the [supported subset](javascript-target.md), and broaden the [real-browser checks](browser-verification.md) beyond the verified Chromium compiler and module-worker baseline. 3. **Local execution — compiler integration and Bun runner implemented:** A host-independent scheduler runs exported module functions in bounded Bun subprocess workers, with queue limits, task-data snapshots, cancellation, deadlines, failure propagation, and confirmed shutdown. See [local runtime](local-runtime.md). Project builds extract module-level parallel functions into task modules; `run` owns their worker lifecycle. Parallel registration follows local named imports, aliases, re-exports, and immutable namespaces. Task bodies can use transitive imported Clio function dependencies through separate task companions. Arbitrary decorators cannot establish a parallel boundary signature. Explicitly typed module data captures now use per-call snapshots and fresh task scopes, including private captures in transitive helpers. Nested scheduling now uses central admission, bounded depth and child counts, cooperative single-worker progress, and root-tree cancellation. Continue compiler coverage alongside the registered-task remote adapter described below. The [browser adapter](browser-runtime.md) now executes compiled typed tasks in module Web Workers, sharing Sia validation and nested scheduling, with real Chromium checks for cancellation, failures, and cleanup. Other browsers and alternative thread hosts remain unverified.
4. **Sia protocol — compiled worker integration implemented:** The compiler emits concrete schemas for arguments, map metadata, and resolved results. Versioned Sia frames preserve float64 Numbers and UTF-16 strings, support typed arrays, declared records, and finite unions, validate schema identity, and bound decoding. Runtime mismatches fail without dynamic fallback. See [Sia protocol v3](sia-protocol.md). Declared record instances now preserve nominal identity, inheritance, and imported types across workers. Explicitly typed data captures are included in concrete call schemas. The remote adapter requires exact deployment and schema identity; cross-version negotiation remains future work. Narrower integer types remain future language additions.

Go-to-definition now follows lexical bindings, local import aliases, and namespace re-exports using unsaved source positions.
