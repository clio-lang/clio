# Roadmap

## Native implementation status

The native rewrite is a working CPU/Apple GPU compute subset, not yet the full accepted language. The released JavaScript prototype is separate. The implementation record below includes historical intermediate states; this table summarizes the current position.

As of 2026-10-18, the main native roadmap is estimated at **60% complete / 40% remaining**. This is a qualitative engineering estimate of remaining effort, not a percentage calculated from test counts or completed micro-milestones. Its scope includes the native language and managed runtime, CPU and GPU capabilities (Apple first, NVIDIA later), modules/libraries, developer tooling, documentation and release qualification.

[Native distributed execution](native-distributed-roadmap.md) and [C/C++ integration](native-interop-roadmap.md) have separate roadmaps and are excluded from this estimate and the main release gates. Shared foundations may support them later; their public contracts and deployment/embedding requirements are not main-roadmap prerequisites.

## Optimization

- **Trusted immutable String query paths:** avoid repeated full UTF-8 validation when compiler/runtime provenance proves a value was already validated. Preserve validation at untrusted descriptor boundaries, cooperative cancellation, exact counts and owner lifetimes. The initial [length queries](design/strings.md#scalar-and-byte-lengths) validate on every call; byte-count retrieval itself is constant time.

Complete missing native functionality before taking on these performance improvements. The current copying reshape implementation remains the baseline; immutable value semantics allow storage sharing but do not require it.

- **Shared-storage tensor reshapes and collection conversions:** avoid copying elements when the source layout is compatible with the requested logical row-major reshape. Retain managed backing for the result's full lifetime, including helper returns, worker captures/results and repeated awaits. Keep an ordered-copy fallback when layout or borrowed-storage lifetime prevents safe sharing. Qualify actual pointer sharing, backing lifetime, empty/rank-zero tensors, offsets, cancellation and failure cleanup before enabling the optimization. Apply the same lifetime qualification to [tensor-to-array construction](design/tensor-array.md#ordering-and-ownership). See the [current reshape implementation](design/tensor-reshape.md#ordering-errors-and-memory).

- **Record collection storage:** replace construction/read copies with shared immutable backing where safe, and reclaim temporary field storage at last use instead of waiting for invocation settlement. Preserve worker retention, shape checks, repeated-await snapshots and failure cleanup.

The [authenticated remote runtime](network-execution.md) is exported through `@kalandra/runtime/bun/remote`, with validated deployment manifests, mandatory bearer authentication, exact revision/schema checks and reservation-based explicit cancellation. Separate-process source and bundled tests verify worker cleanup before cancellation acknowledgement. The listener binds loopback; TLS/proxy deployment and public hosting remain unverified. Project builds now generate deployment/client manifests from explicitly selected exported services, including checked signatures, canonical schemas and deterministic content-based revisions. Source and built acceptance consume these artifacts without discovering registrations by executing modules. Typed service captures now have a [server-startup baseline](remote-service-captures.md) with per-request snapshots. The compiler emits a pure bootstrap and private worker schemas; hosting initializes it in a bounded subprocess before listening. Effectful setup remains rejected. Project builds now type-check `remote:./contract.json` imports and generate pinned remote routing metadata. Independent clients need only their own source and trusted contracts; endpoint/token bindings stay outside compiled artifacts, supplied through the host API or CLI endpoint files. Source and bundled network acceptance cover independent calls, stale contracts, authentication, deadlines and cancellation cleanup. Named/namespace/import-alias and explicit parallel calls work. Local workers can now submit checked remote calls through parent-host routing, with shared nesting limits, per-tree cancellation and cleanup acknowledgement. Remote service chaining uses explicit service-host endpoint bindings, propagated hop limits and cancellation cleanup. Remote record contracts now generate local constructors with preserved argument order, inheritance and nominal identity scoped by deployment revision. Separate-process source/bundled checks cover nested arrays, unions, round trips and invalid input rejection. Local worker signatures now support remote record annotations through aliases, re-exports and immutable namespaces, including nested records and typed captures. Local records can now extend imported remote types with inherited constructor order, shared prototypes and strict nominal identity preserved across local workers, nested tasks and typed captures. Explicit parent construction is required when calling a service that expects the remote parent type. Service exports using imported record declarations remain unsupported. Service builds now register bounded array-map forms without server call sites, including callback metadata and private capture schemas. Independent clients map scalars and records directly or from local workers while retaining strict types and request isolation. The checked-callback extra-argument behavior is tracked as LC-006. Fresh [complete workflows](../examples/workflows/README.md) now combine typed JavaScript interop, inheritance, local nested batches and remote record mapping with server-owned captures. Source and isolated bundled CLI checks verify results, failure recovery, cancellation after workers start, worker exit and listener shutdown. These are new Kalandra acceptance programs, not historical parity claims. Next: review the remaining port gaps against validated historical evidence. The Bun CLI now hosts compiled services and runs clients with endpoint files referencing token environment variables; signal cancellation and mixed local/remote cleanup are covered by source and bundled network acceptance. Checked local remote-service aliases are supported; private direct-call helpers can pass/return a fixed checked remote identity; broader handle escapes and legacy `ws:` imports remain diagnostic.

The [IR-driven supervisor](design/placement-ir.md#ir-driven-supervisor-continuations) now lowers mixed-program control flow from checked values and resolved symbols. The [common continuation planner](design/continuations.md) now drives both CPU task lowering and the Metal supervisor. [Direct resumable helpers](design/continuations.md#resumable-mixed-helper-bodies) now coordinate CPU/GPU tasks, own scopes and return completed host values through transitive calls. [Independently scheduled helper children](design/continuations.md#independently-scheduled-mixed-helpers) now own captures, frames, nested work and completed results on the bounded scheduler. [Checked CPU int32 scalars](design/numbers.md#checked-cpu-int32-scalar-arithmetic) now support contextual literals, ordinary functions and exact executable results, with compile-time/runtime overflow and division checks. [Int32 CPU task continuations](design/numbers.md#int32-cpu-task-captures-and-results) now support typed captures/results, nested workers, mixed numeric packets and supervised arithmetic faults through the same checked MLIR lowering. [Synchronous int32 CPU tensors](design/numbers.md#checked-cpu-int32-tensor-literals-and-elementwise-operations) now support typed literals, ranked elementwise operators and checked native interfaces. [Int32 tensor worker handoff](design/numbers.md#int32-tensor-captures-and-results-in-cpu-tasks) now preserves element-aware captures/results and backing lifetimes across nested tasks, cached awaits and failure recovery. [Checked int32 CPU reduceSum](design/numbers.md#checked-cpu-int32-reducesum) now preserves the balanced-adjacent tree, checks every addition and integrates worker fault recovery. [Checked CPU uint32 scalars](design/numbers.md#checked-cpu-uint32-scalar-arithmetic) now support exact constants/CLI values, unsigned MLIR operations, distinct task layouts and nested Arithmetic recovery. Int64/uint64 tensors, further widths, GPU integer arithmetic, conversions, broader values and modules remain gaps.

**Deferred lower-level access:** [LL-001](design/placement.md#deferred-direct-execution-and-memory-controls-ll-001) tracks immutable updates and more direct execution controls (numeric array/tensor scalar reads now have checked implementations), explicit SIMD/vector operations, custom GPU kernels and finer coordination/memory controls. These are later design work; syntax and unsafe facilities are not accepted yet.

**Native library embedding:** support compiling Kalandra functions to object files and static/shared libraries that C++ and other native hosts can link. Define a stable C ABI and generated headers first, including scalar/tensor representation, checked failures, retained output ownership, runtime initialization/shutdown and task/device lifecycle. Optional C++ wrappers can make that interface easier to use. Private compiler test entry points are not a public ABI commitment. This is tracked native tooling work, not currently supported library packaging.

**Native distributed execution gate:** complete a separate design review of contracts, deployment, transport, cancellation and remote data lifetimes before implementing distributed execution.

**Numerical type expansion:** reuse the scheduler, task/error control flow, ownership, placement and shape machinery. Shared element-type descriptions now replace implied numeric identity and duplicated storage widths. CPU runtime descriptors, retention/copy adapters and scalar task layouts are now element-aware. Additional source arithmetic still requires per-type compiler lowering and qualification before its capability gate can be enabled. Each type still needs its own arithmetic semantics, CPU/GPU capability checks and numerical conformance; floating-point bit algorithms are format-specific.
