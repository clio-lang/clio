# Roadmap

**Active sequence:** finish verified missing Clio implementation, then complete Tiramisu docs/site and small release polish, publish and announce Kalandra, and only afterward address language flaws and new capabilities. The [port-completion queue and release gates](port-completion.md) take priority over future-work suggestions below. PORT-001 (decorated tail calls) and PORT-002 (local emitter behavior) are implemented. PORT-003 now has working historical TCP evidence; PORT-003a (service-host outbound calls) is implemented with source/bundled CLI acceptance. Nine additional historical RPC probes identify PORT-003b (checked local use of remote handles) and the narrower PORT-003c (startup-created local targets); PORT-003b covers aliases plus checked private local helper parameters/synchronous returns; PORT-003c now supports the verified single-instance startup-created target; PORT-004 classified the three original project/cache fixtures and fresh failing cycle probes, finding no missing implementation in that scope; PORT-005 CLI inventory identifies build resources, source documentation access and terminal highlighting as admitted follow-ups; PORT-005a build resources is implemented; PORT-005b static source documentation access is implemented; PORT-005c terminal highlighting is implemented; the [final acceptance sweep](port-acceptance.md) passed; offline scaffolding is implemented; Tiramisu docs/site completion and release packaging are next. Registration collisions are tracked as LC-008.

1. **Syntax baseline — implemented:** Port committed Clio syntax to Chevrotain and an independent AST. Kalandra uses `.kalandra`, `kalandra.toml`, and `.kalandra/modules`, with no Clio migration support. Original historical fixtures remain test evidence only. All 177 positive reference fixtures parse; syntax failures and AST shapes are tested. See [coverage and limits](compiler-port.md). Keep unfinished Clio changes separate.
2. **Compiler path — decorators, local modules, and JavaScript interop implemented:** Single-file resolution and gradual type checking now cover the original type errors, scopes, annotations, imports supplied by the host, and async/parallel metadata. Typed IR and Babel ESM emission now emit 146 of the 177 positive fixture forms, with differential behavior tests and source-map checks under Bun. The local project builder resolves relative/root imports, installed Kalandra packages with manifests, and explicit ESM/CommonJS packages, shares export signatures and runtime helpers, and emits native ESM. CLI build/run discover the nearest enclosing `kalandra.toml` and use its `build.source`, with standalone-file fallback and explicit output destinations. The language server shares manifest discovery, supports unsaved configuration changes, and isolates nested projects during source discovery. Indexed writes now preserve historical bracket lookup, read-back, and evaluation order, including chained targets. Direct self-tail calls in synchronous and async functions, including decorated functions, now run with bounded stack usage and preserve per-invocation closure bindings and explicit await points; explicitly awaited self-calls remain ordinary calls. Arithmetic operands, property-access bases, and supported call targets now lift bindings ahead of their statement, preserving binding order and enclosing-scope visibility. Unresolved semantics and preserved quirks are tracked in the [language design backlog](language-design-backlog.md). Next, expand the [supported subset](javascript-target.md), and broaden the [real-browser checks](browser-verification.md) beyond the verified Chromium compiler and module-worker baseline. The [31-fixture compatibility audit](compatibility-audit.md) now separates contextual support, strict-boundary rejections, historical runtime failures, and deferred work. Preserve existing behavior before language improvements. Add conformance tests alongside each feature.
3. **Local execution — compiler integration and Bun runner implemented:** A host-independent scheduler runs exported module functions in bounded Bun subprocess workers, with queue limits, task-data snapshots, cancellation, deadlines, failure propagation, and confirmed shutdown. See [local runtime](local-runtime.md). Project builds extract module-level parallel functions into task modules; `run` owns their worker lifecycle. Parallel registration follows local named imports, aliases, re-exports, and immutable namespaces. Task bodies can use transitive imported Clio function dependencies through separate task companions. Arbitrary decorators cannot establish a parallel boundary signature. Explicitly typed module data captures now use per-call snapshots and fresh task scopes, including private captures in transitive helpers. Nested scheduling now uses central admission, bounded depth and child counts, cooperative single-worker progress, and root-tree cancellation. Continue compiler coverage alongside the registered-task remote adapter described below. The [browser adapter](browser-runtime.md) now executes compiled typed tasks in module Web Workers, sharing Sia validation and nested scheduling, with real Chromium checks for cancellation, failures, and cleanup. Other browsers and alternative thread hosts remain unverified.
4. **Sia protocol — compiled worker integration implemented:** The compiler emits concrete schemas for arguments, map metadata, and resolved results. Versioned Sia frames preserve float64 Numbers and UTF-16 strings, support typed arrays, declared records, and finite unions, validate schema identity, and bound decoding. Runtime mismatches fail without dynamic fallback. See [Sia protocol v3](sia-protocol.md). Declared record instances now preserve nominal identity, inheritance, and imported types across workers. Explicitly typed data captures are included in concrete call schemas. The remote adapter requires exact deployment and schema identity; cross-version negotiation remains future work. Narrower integer types remain future language additions.
5. **Tooling:** Local project analysis, build, and explicit Git dependency installation with transitive resolution and commit locking are implemented (see [installation](dependency-installation.md)); explicit [JavaScript package declarations](javascript-types.md) now provide export signatures to builds and the language server. Build-only [watch mode](watch-mode.md) now rebuilds changed inputs in sequential fresh compiler processes and recovers after compilation errors. A [comment-preserving formatter](formatter.md) now verifies AST equivalence and supports CLI stdout/check/write modes. The language server also exposes Format Document for unsaved buffers, with UTF-16 edits, stale-snapshot protection, and source/bundled protocol verification. Extend declaration coverage as needed. [LSP diagnostics for unsaved buffers](language-server.md) now work over Bun stdio, with incremental UTF-16 edits, versioned buffers, and shared compiler analysis. Project overlays now propagate unsaved local export signatures, recheck importers, and suppress stale asynchronous results. Go-to-definition now follows lexical bindings, local import aliases, and namespace re-exports using unsaved source positions. Type hover now displays inferred types and function signatures using the same snapshot analysis. Completion now offers lexical names and known members, with cursor recovery and unsaved export signatures. Find-references now follows semantic identities across open graphs, including import aliases, re-exports, and unsaved buffers. Prepare-rename and rename now preserve explicit aliases, propagate export changes through open graphs, and reanalyze proposed edits to reject collisions and capture. Workspace source discovery now includes eligible unopened importers in references and rename, with fixed exclusions, root isolation, scan limits, and explicit failure on incomplete discovery. Configurable source exclusion globs and a bounded session index now reuse unchanged compiler graphs after validating their inputs. Discovery and source reads remain fresh per request. Next, return to the tracked compiler compatibility gaps; on-disk indexing and finer-grained invalidation can follow measured performance needs. Keep semantics shared with the compiler.
6. **Public alpha:** The [Tiramisu docs playground](playground.md) now provides editable single-file examples, diagnostics, console/results, and Run/Stop in a fresh opaque sandbox with worker execution. A [tested Tiramisu language guide](language-guide.md) now covers first programs through parallel execution, using one example catalog for documentation, playground links, and execution tests. Next, finish new-project onboarding, release packaging, and a deployment workflow. Choose publishing and hosting destinations explicitly.

A [fresh project acceptance suite](acceptance-suite.md) now exercises six complete projects through both the source and bundled CLI. Historical examples are excluded from compatibility scoring until they run successfully on a verified old toolchain; the initial Clio probe is environment-blocked, not a language failure. Network work now uses fresh deterministic Kalandra client/server acceptance programs.

A release is ready when a new user can follow the documented path from installation to a useful parallel program and understand a failure without maintainer help.

The [authenticated remote runtime](network-execution.md) is exported through `@kalandra/runtime/bun/remote`, with validated deployment manifests, mandatory bearer authentication, exact revision/schema checks and reservation-based explicit cancellation. Separate-process source and bundled tests verify worker cleanup before cancellation acknowledgement. The listener binds loopback; TLS/proxy deployment and public hosting remain unverified. Project builds now generate deployment/client manifests from explicitly selected exported services, including checked signatures, canonical schemas and deterministic content-based revisions. Source and built acceptance consume these artifacts without discovering registrations by executing modules. Typed service captures now have a [server-startup baseline](remote-service-captures.md) with per-request snapshots. The compiler emits a pure bootstrap and private worker schemas; hosting initializes it in a bounded subprocess before listening. Effectful setup remains rejected. Project builds now type-check `remote:./contract.json` imports and generate pinned remote routing metadata. Independent clients need only their own source and trusted contracts; endpoint/token bindings stay outside compiled artifacts, supplied through the host API or CLI endpoint files. Source and bundled network acceptance cover independent calls, stale contracts, authentication, deadlines and cancellation cleanup. Named/namespace/import-alias and explicit parallel calls work. Local workers can now submit checked remote calls through parent-host routing, with shared nesting limits, per-tree cancellation and cleanup acknowledgement. Remote service chaining uses explicit service-host endpoint bindings, propagated hop limits and cancellation cleanup. Remote record contracts now generate local constructors with preserved argument order, inheritance and nominal identity scoped by deployment revision. Separate-process source/bundled checks cover nested arrays, unions, round trips and invalid input rejection. Local worker signatures now support remote record annotations through aliases, re-exports and immutable namespaces, including nested records and typed captures. Local records can now extend imported remote types with inherited constructor order, shared prototypes and strict nominal identity preserved across local workers, nested tasks and typed captures. Explicit parent construction is required when calling a service that expects the remote parent type. Service exports using imported record declarations remain unsupported. Service builds now register bounded array-map forms without server call sites, including callback metadata and private capture schemas. Independent clients map scalars and records directly or from local workers while retaining strict types and request isolation. The checked-callback extra-argument behavior is tracked as LC-006. Fresh [complete workflows](../examples/workflows/README.md) now combine typed JavaScript interop, inheritance, local nested batches and remote record mapping with server-owned captures. Source and isolated bundled CLI checks verify results, failure recovery, cancellation after workers start, worker exit and listener shutdown. These are new Kalandra acceptance programs, not historical parity claims. Next: review the remaining port gaps against validated historical evidence. The Bun CLI now hosts compiled services and runs clients with endpoint files referencing token environment variables; signal cancellation and mixed local/remote cleanup are covered by source and bundled network acceptance. Checked local remote-service aliases are supported; private direct-call helpers can pass/return a fixed checked remote identity; broader handle escapes and legacy `ws:` imports remain diagnostic.
