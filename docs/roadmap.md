# Roadmap

## Native implementation status

The native rewrite is a working CPU/Apple GPU compute subset, not yet the full accepted language. The released JavaScript prototype is separate. The implementation record below includes historical intermediate states; this table summarizes the current position.

As of 2026-10-21, the main native roadmap is estimated at **approximately 83% complete / 17% remaining**. This revises the previous 82% estimate after checked record/enum/construction/pattern completion, installed-editor acceptance and signature help. It is a coarse estimate of remaining engineering effort, not a percentage calculated from test counts or a fixed increment per feature. Core recursive-value gaps, wider Apple GPU integration, unfinished-code tooling, distribution qualification and the native website/documentation/release remain. The scope includes the native language and managed runtime, CPU and Apple Metal GPU capabilities, modules/libraries, developer tooling, documentation and release qualification.
[CPU compiler installation](design/native-cpu-install.md) now adds a prefix-relative compiler/runtime bundle and relocation/sanitizer acceptance. [Native release automation](design/native-releases.md) builds and qualifies CPU/editor packages on version tags, treating all SemVer prerelease identifiers (including alpha, beta and RC) as prereleases. An initial [Apple Metal compiler bundle](design/native-metal-install.md) now installs private shader tools, host headers and CPU/Metal runtimes with relocation acceptance. The [LLVM 23 migration](design/native-llvm23.md) updates the compiler, shader pipeline compatibility and release provisioning. External dependencies, Metal release-runner qualification, signing/notarization and broader release qualification remain.

[NVIDIA/CUDA](native-cuda-roadmap.md), [native distributed execution](native-distributed-roadmap.md) and [C/C++ integration](native-interop-roadmap.md) have separate roadmaps and are excluded from this estimate and the main release gates. Shared foundations may support them later; their backend, public interface and deployment requirements are not main-roadmap prerequisites. The current estimate also reflects progress on variants, application errors and function values; remaining tooling, GPU integration, platform and release work still carries substantial effort.


[Machine-readable native checker diagnostics](design/native-diagnostics.md) now provide versioned success/failure responses, original module filenames and UTF-16 editor ranges. [Unsaved source checking](design/native-source-overlays.md) now adds owned replacement buffers across module/package graphs and a bounded `--stdin` root-buffer command. The [native language server](design/native-language-server.md) now publishes versioned diagnostics for full and transactional incremental open-buffer updates and rechecks imported buffers. Compiler-backed type hover and go to definition are also implemented, including captured lexical bindings and imported call targets. Bounded references across open/project import graphs now include import/re-export names and aliases, type annotations, record construction/update labels, enum cases and match patterns with distinct shorthand roles. Workspace discovery now includes eligible unopened importers, with fixed exclusions, root isolation, scan limits and explicit failure on incomplete discovery. Prepare-rename and rename now preserve explicit aliases and shorthand roles, rechecking proposed edits to reject collisions and capture. [Package-aware editor analysis](design/native-language-server.md#installed-dependencies) now follows locked private dependency scopes, with read-only installed sources and relocated editor-package qualification. Scope completion, verified native formatting and an installable VS Code client are now implemented and qualified in the real editor host. An initial [native editor-tools installation](design/native-tools-install.md) now supports prefixes and relocatable tool archives with external LLVM dependencies; CPU and initial Apple Metal compiler/runtime bundles now add private resource installation, with self-contained distribution still open.

## Immediate accepted-core queue

Prioritize the remaining accepted core-language requirements after array concatenation. Collection convenience APIs, including slicing and concatenation, are tracked separately from core-language completion.

1. **Core numeric widths (implemented on CPU):** All ten [accepted scalar types](design/numbers.md) support scalars, arrays, tensor construction/elementwise arithmetic, reductions, matrix multiplication and local workers. [Checked CPU tensor numeric conversions](design/narrow-tensor-conversions.md) now complete all 100 source/destination pairs. GPU numeric coverage remains separate. Continue with user-declared variants below.
2. **User-declared variants:** the [first native CPU enum subset](design/native-enums.md) implements ordinary `enum` declarations, payload-free and named scalar/collection/nested variants, exhaustive matching, immutable ownership and local worker transport. Enum values also work in records and arrays. Numeric arrays/tensors, Bool/String arrays and nested records/enums are now supported as payload fields, following the [accepted variant design](design/variants.md). [Arrays of records/enums](design/record-array-fields.md) are now supported as record and enum payload fields, including retained nested backing through CPU workers. Recursive payloads require a separate representation decision. Built-in TaskError matching does not count as user-defined application errors.
3. **Application error channels:** [local single-family channels](design/application-errors.md) now implement declared `error` types, typed `fail`/`try`/`catch`, early failure guards, handler replacement and unhandled CLI reporting. [Local application-family unions and aliases](design/error-unions.md) now add canonical aliases, subset propagation and exhaustive union handlers. [Local mixed channels](design/mixed-error-channels.md) now include `TaskError`, preserving task details, typed fields and independent CLI reporting. [Local CPU worker transport](design/worker-errors.md) now preserves application errors across `spawn`/`await` and parallel settlement as `E | TaskError`, following the [accepted errors](design/errors.md) and [variant](design/variants.md) contracts. Keep application errors distinct from execution failures. [Error aliases in record/enum payload fields](design/error-payload-fields.md) now preserve completed error values, nested payloads and TaskError data. [Whole-value match-arm narrowing](design/error-narrowing.md) now preserves selected and residual error-family sets, including TaskError, across rethrows, helpers and callbacks. Continue with function values below.

5. **Proper parallel map (initial CPU implementation):** [`parallelMap(values, callback)`](design/native-parallel-map.md) and `try (values -> parallelMap(callback))` now schedule bounded CPU element tasks, preserve result order, carry callback/TaskError channels, and settle before returning. Users do not write recursive split/spawn/join helpers. Named and inline nested callbacks share the worker pool. The initial eight-task batches reclaim completed groups and fill one output array; scheduler resource limits still apply. Adaptive granularity, wider/configurable windows and throughput tuning remain optimization work. [Proven coordinating bound callbacks](design/native-resumable-callables.md) are now supported on CPU; unknown targets, recursive coordinating graphs and placement-aware/GPU callbacks remain separate work.

- **Delimited anonymous suites (implemented):** [indented callbacks inside calls and collections](design/native-delimited-closures.md) preserve ordinary multiline arguments, source spans, diagnostics and compiler budgets. This adds syntax without changing closure execution or ownership. Other standalone indented expressions inside delimiters remain separate syntax work.

This queue identifies the next core gaps; it does not replace the remaining GPU, modules, tooling, platform and release work in the status table. Further collection convenience APIs are deferred while this queue is addressed. NVIDIA/CUDA, distributed execution and C/C++ integration retain their separate roadmaps.

CPU and GPU feature coverage is explicit: shared syntax, types and IR do not imply that every CPU value or runtime feature must execute on GPU. GPU-compatible numeric computation remains main-roadmap work; managed closures, strings and host task control are not automatically device capabilities. Unsupported device programs retain compile-time diagnostics until their lowering and memory behavior are qualified.

## Platform qualification order

Qualify macOS ARM64 with Metal first. CPU toolchain/runtime qualification for Windows x86-64, Linux and then FreeBSD remains planned; other BSD systems need individual qualification. NVIDIA GPU support on Windows and Linux belongs to the [separate CUDA roadmap](native-cuda-roadmap.md) and does not block the main roadmap. LLVM code generation does not by itself establish runtime, linker, packaging or operating-system support. Other GPU backends, including OpenCL, follow concrete hardware/deployment needs and are not prerequisites for the first native release. These are planned targets, not a claim of current support.

## Advanced GPU interoperability — planned follow-up

These are two separate future workstreams, deferred until after the current generated-kernel integration baseline. Neither expands the immediate core queue or adds a prerequisite to the current native release gates. Public APIs and syntax are not accepted yet.

### User-supplied compute shaders and kernels

Let applications supply custom GPU computation for specialized operations not expressed by the supported Kalandra subset. Start with Apple Metal; backend-specific CUDA artifacts follow the separate NVIDIA roadmap.

Define typed tensor/scalar bindings, output shapes, device requirements, dispatch configuration, source versus precompiled artifact loading and packaging. Integrate immutable input ownership, fresh result storage, retained resources through command completion, explicit transfers, budgets and existing task error/cancellation settlement. Cancellation must not imply that an already submitted GPU command can be forcibly stopped.

Specify the foreign-code safety and numerical boundary: reflection/layout checks alone cannot prove an arbitrary shader's memory accesses, immutability or arithmetic semantics. Do not silently grant user-supplied shaders the guarantees of compiler-generated kernels.

### External GPU compute libraries

Let applications reuse existing optimized operations through library adapters, separately from loading custom shaders. Candidate integrations include Metal Performance Shaders on Apple and cuBLAS under the separate NVIDIA roadmap; these are examples, not selected dependencies or implementation commitments.

Define supported operations, tensor formats/layouts, device compatibility, dependency packaging and task completion integration. Preserve Kalandra ownership and explicit transfer rules. Specify numerical compatibility per operation; a library operation must not silently replace a strict language operation when rounding, reduction order or other semantics differ. Evaluate usefulness and implementation scope before selecting the first adapter. Shared resource/dispatch foundations may be reusable, but library adapters and custom-kernel loading have distinct interfaces and qualification work.

## Optimization

- **Deep tensor-choice compile time:** profile and bound MLIR One-Shot Bufferize alias analysis for long tensor-valued `if`/`else` chains in the CPU shadow functions used for GPU admission. A linear 40-leaf choice after summing 40 dynamic tensor parameters exposes pathological scaling; the 40-source qualification uses a single choice over two tensor expressions. GPU source arity and this compile-time issue are separate concerns.
- **Conditional GPU graph bindings:** investigate projected direct bindings for small scalar-control graphs. The current [argument-buffer path](design/native-gpu-scalar-control.md#strict-lowering) preserves declared resources when optimization removes a predicate or identical arm. Derive any replacement from the lowered shader interface and preserve exact binding indices, capture budgets and failure/lifetime behavior.

- **Parallel-map scheduling:** tune task/chunk granularity, bounded window width and capacity-aware admission; reduce repeated capture copying and avoid whole-batch straggler stalls. Preserve ordered results, typed failures, cooperative cancellation and resource accounting. The initial [CPU implementation](design/native-parallel-map.md) uses up to eight element tasks per batch.

- **Trusted immutable String query paths:** avoid repeated full UTF-8 validation when compiler/runtime provenance proves a value was already validated. Preserve validation at untrusted descriptor boundaries, cooperative cancellation, exact counts and owner lifetimes. The initial [length queries](design/strings.md#scalar-and-byte-lengths) validate on every call; byte-count retrieval itself is constant time.

Complete missing native functionality before taking on these performance improvements. The current copying reshape implementation remains the baseline; immutable value semantics allow storage sharing but do not require it.

- **Shared-storage tensor reshapes and collection conversions:** avoid copying elements when the source layout is compatible with the requested logical row-major reshape. Retain managed backing for the result's full lifetime, including helper returns, worker captures/results and repeated awaits. Keep an ordered-copy fallback when layout or borrowed-storage lifetime prevents safe sharing. Qualify actual pointer sharing, backing lifetime, empty/rank-zero tensors, offsets, cancellation and failure cleanup before enabling the optimization. Apply the same lifetime qualification to [tensor-to-array construction](design/tensor-array.md#ordering-and-ownership) and [array slices](design/array-slicing.md#storage-and-execution-scope), including interior offsets and retained String/record child storage. Include the [numeric indirect-call descriptor adapters](design/native-function-values.md#collection-parameters-and-results), which currently pack/unpack copies at each call boundary. Preserve checked shape validation, borrowed/strided input ordering, invocation isolation, retained worker data and allocation-failure cleanup when eliminating those copies. See the [current reshape implementation](design/tensor-reshape.md#ordering-errors-and-memory).

- **Record collection storage:** replace construction/read copies with shared immutable backing where safe, and reclaim temporary field storage at last use instead of waiting for invocation settlement. Preserve worker retention, shape checks, repeated-await snapshots and failure cleanup.

- **Resumable callable dispatch:** compact finite-target continuation specialization, reduce repeated validated environment copies and qualify a bounded continuation stack before supporting recursive coordinating function values. Preserve runtime target selection, typed errors, cancellation, provenance and ownership. See [CPU resumable callables](design/native-resumable-callables.md).

- **Closure environments:** eliminate or specialize capture allocations where proven safe, share immutable numeric backing instead of descriptor packing copies, and reclaim environments and transitive captures after their last use. Preserve distinct creator environments, nested captures, checked failures and invocation/worker lifetimes. The initial implementation keeps managed environments until invocation settlement.

- **Bounded recursive execution:** qualify explicit heap-stack/trampoline execution or proven tail calls for deep recursion, and replace the conservative native-stack estimate with more precise admission where safe. Preserve call-limit faults, source errors, cancellation, owned outcomes and balanced invocation-local call slots. The current [recursive implementation](design/native-recursive-callables.md) uses a 128-entry budget, Apple stack headroom and a conservative per-function stack estimate.

- **Synchronous callable frames:** specialize direct targets and reuse or eliminate temporary frames where proven safe. Expected-error/control-flow function values and direct control-flow map callbacks currently allocate a checked invocation-owned frame per call, which can accumulate across large maps. Preserve evaluation order, typed outcomes, original fault locations, cancellation, retained payload lifetimes and allocation-failure cleanup. This optimization does not require source allocator annotations.

- **Compact enum storage and dispatch:** replace the first [fully initialized tagged aggregate](design/native-enums.md) with a compact active-payload representation and scalable switch dispatch. Preserve nominal identity, source evaluation order, exhaustive matching and managed payload lifetimes through workers. The current compiler depth budgets remain explicit until dispatch is qualified. This is an optimization, not a change to source variant semantics or a public ABI promise.

**GPU graph stage fusion:** after correctness qualification, combine compatible
adjacent arithmetic stages to reduce command and intermediate-storage overhead.
Preserve source operand order, strict float32 rounding and final-use ownership;
this is optimization work rather than new source syntax.

The [common continuation planner](design/continuations.md) now drives both CPU task lowering and the Metal supervisor. [Direct resumable helpers](design/continuations.md#resumable-mixed-helper-bodies) now coordinate CPU/GPU tasks, own scopes and return completed host values through transitive calls. [Independently scheduled helper children](design/continuations.md#independently-scheduled-mixed-helpers) now own captures, frames, nested work and completed results on the bounded scheduler. [Shared numeric descriptions](design/numbers.md#shared-numeric-descriptions-in-the-native-implementation) now carry concrete identity, family and width through typed IR and checked storage sizes, with float32-only arithmetic gates. [Element-aware CPU storage and adapters](design/numbers.md#element-aware-cpu-runtime-storage-and-adapters) now validate typed tensor leases/copies and distinct scalar task layouts without changing float32 arithmetic. [Checked CPU int32 scalars](design/numbers.md#checked-cpu-int32-scalar-arithmetic) now support contextual literals, ordinary functions and exact executable results, with compile-time/runtime overflow and division checks. [Int32 CPU task continuations](design/numbers.md#int32-cpu-task-captures-and-results) now support typed captures/results, nested workers, mixed numeric packets and supervised arithmetic faults through the same checked MLIR lowering. [Synchronous int32 CPU tensors](design/numbers.md#checked-cpu-int32-tensor-literals-and-elementwise-operations) now support typed literals, ranked elementwise operators and checked native interfaces. [Int32 tensor worker handoff](design/numbers.md#int32-tensor-captures-and-results-in-cpu-tasks) now preserves element-aware captures/results and backing lifetimes across nested tasks, cached awaits and failure recovery. [Checked int32 CPU reduceSum](design/numbers.md#checked-cpu-int32-reducesum) now preserves the balanced-adjacent tree, checks every addition and integrates worker fault recovery. [Checked int32 CPU matmul](design/numbers.md#checked-cpu-int32-matmul) now checks each product and tree sum, returns retained matrices through nested workers and supports supervised Arithmetic recovery. [Checked CPU uint32 scalars](design/numbers.md#checked-cpu-uint32-scalar-arithmetic) now support exact constants/CLI values, unsigned MLIR operations, distinct task layouts and nested Arithmetic recovery. [Synchronous uint32 CPU tensors](design/numbers.md#checked-cpu-uint32-tensor-literals-and-elementwise-operations) now support exact literals, unsigned elementwise checks, scalar lifting and checked native interfaces. [Uint32 tensor worker handoff](design/numbers.md#uint32-tensor-captures-and-results-in-cpu-tasks) now preserves distinct unsigned/signed/float layouts and retained backing across nested tasks, cached awaits and recovery. [Checked CPU uint32 reduceSum](design/numbers.md#checked-cpu-uint32-reducesum) now reuses the adjacent reduction tree and shared integer conformance harness, with unsigned overflow checks and worker fault recovery. [Checked CPU uint32 matmul](design/numbers.md#checked-cpu-uint32-matmul) now reuses integer matrix loops, checked unsigned products/tree sums and retained worker results, with shared signed/unsigned conformance. [Checked CPU int64 scalars](design/numbers.md#checked-cpu-int64-scalar-arithmetic) now support the int alias, default whole-number inference, exact CLI values, width-aware checked lowering and mixed-width worker captures/results. [Checked CPU uint64 scalars](design/numbers.md#checked-cpu-uint64-scalar-arithmetic) now support the uint alias, full-range constants/CLI values, width-aware unsigned lowering and five-family worker captures/results. Int64/uint64 tensors, further widths, GPU integer arithmetic, conversions, broader values and modules remain gaps.

**Deferred lower-level access:** [LL-001](design/placement.md#deferred-direct-execution-and-memory-controls-ll-001) tracks immutable updates and more direct execution controls (numeric array/tensor scalar reads now have checked implementations), explicit SIMD/vector operations, custom GPU kernels and finer coordination/memory controls. These are later design work; syntax and unsafe facilities are not accepted yet.

**Native library embedding:** support compiling Kalandra functions to object files and static/shared libraries that C++ and other native hosts can link. Define a stable C ABI and generated headers first, including scalar/tensor representation, checked failures, retained output ownership, runtime initialization/shutdown and task/device lifecycle. Optional C++ wrappers can make that interface easier to use. Private compiler test entry points are not a public ABI commitment. This is tracked native tooling work, not currently supported library packaging.

**Native distributed execution gate:** complete a separate design review of contracts, deployment, transport, cancellation and remote data lifetimes before implementing distributed execution.

**Numerical type expansion:** reuse the scheduler, task/error control flow, ownership, placement and shape machinery. Shared element-type descriptions now replace implied numeric identity and duplicated storage widths. CPU runtime descriptors, retention/copy adapters and scalar task layouts are now element-aware. Additional source arithmetic still requires per-type compiler lowering and qualification before its capability gate can be enabled. Each type still needs its own arithmetic semantics, CPU/GPU capability checks and numerical conformance; floating-point bit algorithms are format-specific.
