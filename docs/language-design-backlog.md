# Language design backlog

Port first, redesign afterward. This tracker records ambiguous or broken Clio behavior separately from compatibility work. An entry is not approval to change the language. Keep unresolved cases diagnostic; retain tested historical behavior until a later design decision. Update this file when porting uncovers another issue or establishes a reliable baseline.

The reference is Clio commit `75c7c09e962ef15506ff9bc7cf856aad727436c5`, principally `packages/core/types.js`. Current executable coverage and remaining engineering work live in [JavaScript target](javascript-target.md) and [roadmap](roadmap.md).

## Await-all issue established by the fixture audit

**LD-007:** Fixtures #108 and #113 emit `Promise.all(singleParallelCallPromise)`, which throws TypeError because the promise itself is not iterable. This is reproducible in both saved Clio JavaScript and Kalandra project execution. Current behavior still compiles and fails at runtime; decide later whether to reject this statically or change await-all semantics. Plain `await` on a mapped array also leaves its elements unresolved: fixtures #106, #111 and #112 are rejected when those promises reach a typed worker consumer, consistent with the agreed strict Sia boundary. No relaxation of that boundary is proposed. See the [31-fixture audit](compatibility-audit.md).

**LC-006:** `@check` validates every supplied argument against `@params`. Map callbacks append the index and source collection, so annotating only the item causes a runtime TypeError for unannotated extras. This also applies to remote maps; network acceptance retains the failure. Annotate the item, index and collection when using a checked callback. Decide whether checks should ignore undeclared extras during the language-design phase.

**LC-007:** Local emitters retain plain-object listener tables. Names colliding with inherited properties (for example `__proto__`) can throw instead of registering. Differential tests retain this historical behavior; safe event-name storage belongs to the later design phase. Dispatch is synchronous, duplicate callbacks are retained, and returned promises are not awaited.

## Explicitly recorded implementation divergences

- Arithmetic declaration lifting handles either side being absent; the old emitter spreads an undefined declaration list in that case. This repairs a compiler failure without inventing a new evaluation order.
- Installed Kalandra package lookup consistently uses the package manifest’s `build.source`; the pinned resolver mixed the importer’s candidate source directory with the package’s compilation directory. Directory candidates are skipped rather than compiled. See [project resolution](project-build.md).
- Native ESM and the managed Sia 2 worker protocol replace the old module factory and registration model. See [project builds](project-build.md) and [Sia protocol](sia-protocol.md).
- Strict parallel boundaries reject unknown/dynamic values; Number uses float64. These are already agreed decisions, not deferred questions.

Use the [port-completion queue](port-completion.md) for missing implementation. Decorated direct tail calls, explicit JavaScript declarations and browser workers are implemented. Fresh self/mutual import probes overflow the pinned compiler stack (PORT-004); Kalandra retains KAL4102. General cycle support remains later design work. Explicitly awaited self-calls are not optimized by the pinned recursive-call recognizer; changing that is not an established parity requirement.

Direct unawaited tail calls in async functions now use the same loop transformation as synchronous functions. The pinned emitter selects recursiveReturn without an async restriction, then marks the enclosing function async from its body. This port preserves explicit await boundaries; it does not settle LD-006 or optimize awaited self-calls.

## Managed remote capture lifetime

The [remote service capture specification](remote-service-captures.md) defines a server-owned startup baseline and fresh typed snapshots per request, consistent with managed local task isolation. This is an explicit execution-model decision, not a claim of historical mutable-state compatibility. The pure-initializer subset is implemented; effectful setup and subsequent module-level writes still fail compilation. Effectful startup hooks, host-supplied capture configuration and persistent shared service state remain deferred; this decision does not resolve LD-001 through LD-007.

Local emitter host adaptations: generated portable code uses `resource = null` instead of allocating the old unused Node AsyncResource, and reconstructs registered RegExp text without `eval`. Injecting executable text into internal regex tables is not an event API capability. Normal listener behavior is checked against the original runtime snapshot.

## LC-008: function-local parallel registration identity

The pinned compiler registers every closure created from a nested declaration under the same module/name path. The original TCP edge probe initializes two closures with offsets 1 and 3 before worker connection, then calls the first in parallel with 5. It returns 8: the second registration replaced the first function. A single startup-created instance returns 6. Targets created during a request were present in the worker map but absent from the dispatcher registry and timed out.

These are historical registration/lifetime limitations, not permission to invent dynamic closure serialization. PORT-003c implements the demonstrated single-instance startup capability with extracted code and typed capture snapshots. Multiple-instance identity and dynamic registration need a later semantic decision; keep ambiguous cases diagnostic. The strict prohibition on serializing arbitrary functions remains in force. See the saved `rpc-edges.json` probes and the port-completion report for harness limitations.
