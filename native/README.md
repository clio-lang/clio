# Kalandra native development

[CPU Bool values and scalar comparisons](../docs/design/booleans.md) support immutable Boolean literals, functions, strict comparisons across the six CPU numeric types, and typed worker captures/results. [CPU conditionals and short-circuit operators](../docs/design/control-flow.md) now support selected execution, scoped values, retained tensors and resumable worker branches. Bool tensors and GPU Bool execution remain separate work.

The fresh compiler is written in **C++23**, with direct LLVM/MLIR C++ integration. CMake configures the build, Ninja builds it, and CTest runs the tests. Bun and Node are not dependencies of this native development path.

The `native` branch contains the fresh language design and compiler. The released JavaScript prototype and Tiramisu website are separate from this build. The handwritten lexer/parser, [semantic stage](../docs/design/semantics.md), and [native source compiler](../docs/design/native-codegen.md) support float32 arithmetic, ranked dense float32 tensors, and [checked int32 CPU scalars](../docs/design/numbers.md#checked-cpu-int32-scalar-arithmetic). Int32 literals, ordinary functions and executable results preserve exact integer values, with overflow/division faults checked in every build; [CPU worker tasks](../docs/design/numbers.md#int32-cpu-task-captures-and-results) now preserve int32 captures/results and reuse checked MLIR arithmetic, including supervised Arithmetic faults and recovery. [Synchronous int32 tensors](../docs/design/numbers.md#checked-cpu-int32-tensor-literals-and-elementwise-operations) now support literals, ranked elementwise operations and checked native interfaces. [Int32 tensor worker handoff](../docs/design/numbers.md#int32-tensor-captures-and-results-in-cpu-tasks) now retains typed captures/results through nested tasks, repeated awaits and fault recovery. [Checked CPU int32 reduceSum](../docs/design/numbers.md#checked-cpu-int32-reducesum) now supports ranked and empty inputs, deterministic checked tree additions and worker fault recovery. [Checked CPU int32 matmul](../docs/design/numbers.md#checked-cpu-int32-matmul) now supports checked products/tree accumulation, empty shapes and retained worker results. [Checked CPU uint32 scalars](../docs/design/numbers.md#checked-cpu-uint32-scalar-arithmetic) now support unsigned constants/operators, exact CLI values and mixed/nested worker tasks. [Synchronous uint32 tensors](../docs/design/numbers.md#checked-cpu-uint32-tensor-literals-and-elementwise-operations) now support literals, ranked checked elementwise arithmetic and scalar lifting. [Uint32 tensor worker handoff](../docs/design/numbers.md#uint32-tensor-captures-and-results-in-cpu-tasks) now preserves typed captures/results and ownership through nested tasks, cached awaits and fault recovery. [Checked CPU uint32 reduceSum](../docs/design/numbers.md#checked-cpu-uint32-reducesum) now supports ranked/empty inputs, full-range scalar results, checked tree additions and worker fault recovery through shared reduction machinery. [Checked CPU uint32 matmul](../docs/design/numbers.md#checked-cpu-uint32-matmul) now supports exact unsigned products/tree sums, empty shapes, retained nested worker results and Arithmetic recovery. [Checked CPU int64 scalars](../docs/design/numbers.md#checked-cpu-int64-scalar-arithmetic) now support the int alias, default whole-number literals, exact 64-bit CLI values and mixed-width worker calls with checked overflow. [Checked CPU uint64 scalars](../docs/design/numbers.md#checked-cpu-uint64-scalar-arithmetic) now support the uint alias, exact full-range output, checked unsigned arithmetic and mixed-width worker calls. [Shared int64/uint64 tensor literals and elementwise arithmetic](../docs/design/numbers.md#shared-int64uint64-cpu-tensor-literals-and-elementwise-arithmetic) now use the existing checked scalar operations lane by lane, with eight-byte storage and allocation checks. [Shared int64/uint64 tensor worker handoff](../docs/design/numbers.md#shared-int64uint64-tensor-captures-and-results-in-cpu-tasks) now retains typed captures/results through nested workers, cached awaits, fault recovery and returned values outliving their workers. [Shared checked int64/uint64 reductions](../docs/design/numbers.md#shared-checked-int64uint64-cpu-reducesum) now use exact adjacent-pair additions, eight-byte scratch storage and the existing worker failure/recovery paths. [Shared checked int64/uint64 matrix multiplication](../docs/design/numbers.md#shared-checked-int64uint64-cpu-matmul) now preserves exact products and adjacent-tree sums, empty shapes, retained worker results and Arithmetic recovery. [CPU float64 scalars](../docs/design/numbers.md#cpu-float64-scalar-source-and-worker-integration) now support the float alias, default decimal/exponent literals, strict separately rounded arithmetic, 17-digit CLI output and typed nested worker calls. [Synchronous CPU float64 tensors](../docs/design/numbers.md#cpu-float64-tensor-literals-and-elementwise-arithmetic) now support ranked literals and strict elementwise operations with eight-byte storage. [Float64 tensor worker handoff](../docs/design/numbers.md#float64-tensor-captures-and-results-in-cpu-tasks) now preserves distinct typed layouts, retained backing and exact values through nested/cached calls and recovery. [CPU float64 reduceSum](../docs/design/numbers.md#cpu-float64-reducesum) now supports strict ranked/empty reductions and nested worker results through the existing adjacent-pair tree. [CPU float64 matmul](../docs/design/numbers.md#cpu-float64-matmul) now uses strict separately rounded products and adjacent-tree sums, with retained nested worker results. [Explicit CPU scalar conversions](../docs/design/numbers.md#explicit-cpu-scalar-numeric-conversions) now support all 36 pairs among these six types, including strict rounding, checked failures and direct worker calls. [Explicit CPU tensor conversions](../docs/design/tensors.md#explicit-cpu-element-conversions) now preserve shape across all 36 pairs. GPU conversions, further arithmetic types and GPU integer/float64 arithmetic remain unsupported. [Local tasks](../docs/design/native-tasks.md) support parallel blocks, spawn, await, and TaskError propagation through native continuations. A bounded pool now executes independent CPU tasks concurrently; set `KALANDRA_WORKERS=1..64` to override the detected count (capped at eight by default). Generated loops cooperate with cancellation. The [CPU scaling benchmark](benchmarks/README.md) now measures warmed generated kernels and scheduling overhead; results depend strongly on task size. See the [frontend grammar and limits](../docs/design/frontend.md).

The [Apple GPU comparison](../benchmarks/results/native-gpu-2026-10-15-normalization.md) measures strict arithmetic after replacing per-bit normalization loops with five integer stages. It reduces 256-square matmul GPU command latency by 3.09× on the tested M2 Max; CPU still has lower latency on the tested matmul shapes.

The [shape-selected GPU matmul report](../benchmarks/results/native-gpu-2026-10-15-selection.md) now qualifies automatic two-row/quad entry selection for a conservative M2 Max profile. Other shapes/devices retain the strict scalar GPU entry. Both resident and transfer-inclusive comparisons retain raw timing/control variability.

## Build and test

On the currently validated macOS ARM64 setup:

```sh
cmake --preset native
cmake --build --preset native
ctest --preset native
```

The [toolchain lock](toolchain-proof/toolchain.json) selects LLVM/MLIR/Clang 22.1.8. CMake uses its installed Homebrew keg without changing global PATH. Override the location on initial configure with `-DKALANDRA_LLVM_ROOT=/path/to/llvm-22.1.8` or the corresponding environment variable. An existing CMake cache takes precedence over an environment change.

CMake 3.28 or newer and Ninja are required; the development machine has CMake 4.4.2 and Ninja 1.13.2. Matching compiler and LLVM/MLIR library versions are checked during configuration. A compiler that cannot build the required C++23 facilities fails the build rather than selecting an older language mode. Debug and release configurations must preserve the numerical contract.

A clean configure, build, and the original five toolchain CTest tests also pass with PATH restricted to `/usr/bin:/bin`, invoking CMake/Ninja by absolute paths. This verifies that the native path does not depend on Bun/Node being discoverable.

## Implementation conventions

- Use C++23 with compiler extensions disabled. Add standard-library features only after validating them with the supported compiler and platform library.
- Prefer values, RAII, `std::unique_ptr` for unique ownership, and stable source-buffer ownership for any borrowed source spans. Raw pointers/references express documented non-owning access, not hidden ownership.
- Use `std::expected` for recoverable frontend/IO diagnostics. Treat invalid source as a reported error, not an assertion failure. Unexpected process-level allocation failure needs a separate top-level policy before the compiler accepts arbitrary inputs.
- Keep source locations, AST, resolution/type checking, and lowering separate. Build a focused lexer/parser for the fresh syntax; do not reproduce the prototype's parser ambiguities.
- Keep MLIR contexts/modules under their owning API wrappers, verify constructed IR, and preserve shape, failure, and numerical semantics through lowering.
- Keep templates and abstractions small and useful. C++ implementation complexity should not become language syntax or user-facing memory management.
- Test behavior and diagnostics through CTest. Use sanitizers for relevant native memory paths, while keeping their coverage limits explicit.

Compiler implementation ownership is separate from Kalandra's automatic memory model. Using RAII inside the compiler does not require Kalandra authors to write destructors, allocators, or lifetime annotations.

/opt/homebrew/Cellar/llvm/22.1.8/bin/clang-format --dry-run --Werror \
  native/tools/*.cpp native/lib/*.cpp native/include/kalandra/*.h \

Use `kalandrac --sanitize` for generated AddressSanitizer checks plus the ASan/UBSan runtime, or `--thread-sanitize` for a separate fully instrumented ThreadSanitizer build. ## Apple GPU toolchain proof

An opt-in [Metal proof](metal-proof/README.md) now runs MLIR GPU kernels through SPIR-V and SPIRV-Cross on Apple Silicon. It validates buffer bindings, explicit copies, partial workgroups, and completion. IEEE edge probes expose a strict float32 compatibility gap, so this is not yet Kalandra GPU source support. The [backend contract](../docs/design/apple-gpu.md) records the implementation gates; CPU builds do not require the optional shader tools.

## Apple device, transfer, and compute runtime

The optional [Metal runtime](metal/README.md) now provides immutable host/device buffers and upload/download tasks integrated with CPU task groups. External completion leases keep pending GPU resources alive through cancellation and resume tasks without blocking workers. Transfer tests include nested groups, exact bit preservation, resource budgets, allocation failures, and sanitizer coverage. A private checked kernel interface now dispatches strict float32 addition/multiplication over rank-one device buffers, with explicit downloads, shared resource budgets, and cancellation-safe completion. The optional [source-to-Metal slice](../docs/design/apple-gpu.md#first-source-to-metal-compiler-slice), selected through `kalandrac --target metal`, now compiles a bounded rank-one float32 program with explicit transfers and placed calls into a runnable native executable/shader bundle. It uses generated C++ supervisor continuations and source-generated strict GPU MLIR. A checked [CPU tensor bridge](../docs/design/apple-gpu.md#common-compiler-entry-and-cpu-tensor-abi) now retains CPU-owned inputs for GPU transfers and exports downloaded results as invocation-owned descriptors consumed by MLIR-generated CPU code. Ordinary float32 CPU functions now coexist with GPU functions in one source file, including CPU tensor factories/returns, CPU reductions after explicit downloads, and scalar or host-tensor main results. See [mixed source scope and ownership](../docs/design/apple-gpu.md#mixed-cpugpu-source-programs). Runtime guards check dynamic CPU result shapes at execution boundaries. The same helper definition now compiles for CPU and GPU from shared typed tensor/scalar IR, including strict elementwise arithmetic and scalar lifting. See [shared helper scope](../docs/design/apple-gpu.md#shared-cpugpu-helpers). GPU elementwise entries now use signature-sized owned tensor/scalar captures, with direct bindings for small calls, Tier 2 argument buffers above 29 contributing inputs, and a separate capture-memory budget; see [GPU entry parameters](../docs/design/apple-gpu.md#gpu-entry-scalar-parameters). Direct rank-one/rank-two `reduceSum` entries now execute the accepted fixed tree on GPU and return scalar task results, copying only the final four bytes back to the host; see [reduction scope](../docs/design/apple-gpu.md#rank-one-gpu-reductions) and [resident matrix composition](../docs/design/apple-gpu.md#rank-two-gpu-reductions). Direct rank-two `matmul` entries now preserve separately rounded products and the fixed sum tree on GPU; the mixed source bridge also carries matrix literals, CPU calls/returns and axis-specific guards. See [matrix scope](../docs/design/apple-gpu.md#rank-two-gpu-matrix-multiplication). Rank-two elementwise helpers now preserve full shapes across GPU calls and support strict scalar lifting and transitive helpers, completing a resident matmul → adjust → reduceSum path; see [matrix pipeline scope](../docs/design/apple-gpu.md#rank-two-gpu-elementwise-helpers). Shared placement-aware IR and the [common continuation planner](../docs/design/continuations.md) now serve the current CPU/Metal subset. Resumable mixed helper bodies and broader value/element types remain subsequent work.

## Strict GPU float32 arithmetic

An optional [integer MLIR lowering](../docs/design/strict-gpu-float32.md) now implements scalar float32 add/subtract/multiply/divide and exact sign-bit negation with gradual underflow, signed zero, and nearest/ties-to-even rounding. CPU LLVM and M2 Max Metal results match independent APFloat and CPU references, including separately rounded multiply-then-add. The optional source compiler uses this lowering for its first elementwise placement subset. Other arithmetic remains unsupported; the integer path has an [initial CPU/Metal performance baseline](../benchmarks/results/native-gpu-2026-10-15.md), including separate device-command and managed transfer/residency timings. GPU matmul optimization remains necessary on the tested shapes.

The shared source arithmetic now includes vector/matrix subtraction, either scalar operand order and transitive scalar-negation helpers. The [source conformance and qualification](../docs/design/apple-gpu.md#strict-tensor-subtraction-and-scalar-negation) retain shape guards, owned captures and cancellation-safe lifetimes on CPU and GPU. [Whole-tensor unary negation](../docs/design/apple-gpu.md#whole-tensor-unary-arithmetic) now shares exact sign-bit behavior through CPU and GPU helpers and CPU task extraction. GPU-ABI-001 remains open for broader types and tensor operations.

The [signature-sized GPU argument path](../docs/design/apple-gpu.md#signature-sized-gpu-captures) removes the former two-tensor/eight-scalar storage arrays, preserving source argument order and checked bindings. The [compact GPU binding path](../docs/design/apple-gpu.md#unused-tensor-arguments-and-shape-obligations) now supports unused tensor parameters and operation-derived shape obligations, including 40 logical tensor arguments with one bound input. The [Tier 2 argument-buffer path](../docs/design/apple-gpu.md#tier-2-argument-buffers-for-large-gpu-calls) now handles 40 contributing inputs with reflected, invocation-owned resource storage. GPU-ABI-001 still tracks broader operations and types.

[Strict float32 division](../docs/design/apple-gpu.md#strict-tensor-division) now supports tensor/tensor and either scalar/tensor order, including transitive scalar reciprocal helpers. Division retains separately rounded results rather than becoming multiplication by a reciprocal.

[Inline CPU expressions](../docs/design/apple-gpu.md#inline-cpu-expressions-in-mixed-programs) now compose with explicit GPU placement and transfers. Mixed-program `main` can directly calculate `reduceSum((matmul(host, weights) - 1) / 2)` using the shared checked CPU lowering. Device tensors still require a download before CPU arithmetic; this adds no automatic placement or transfer.

[CPU tasks in mixed programs](../docs/design/apple-gpu.md#cpu-tasks-in-mixed-programs) now share the scheduler with GPU tasks. Use `spawn project(input, weights)` or `spawn project(input, weights) on devices.cpu()`, then observe the result with `try await`. Captures own their immutable inputs; CPU↔GPU transfers remain explicit.

[Nested mixed parallel scopes](../docs/design/apple-gpu.md#nested-parallel-scopes-in-mixed-programs) now group CPU work, GPU work and explicit transfers within `try parallel` expressions in `main`. Inner blocks join before continuing, preserve tensor residency and ownership, and support lexical shadowing. The scheduler's depth, group and task budgets still apply.

[Scoped mixed TaskError recovery](../docs/design/apple-gpu.md#scoped-taskerror-recovery-in-mixed-programs) now handles a completed `parallel` result with `catch`, exhaustive error matching and handler-local `try`/`fail`. Handlers run after group settlement; faults in the supervisor remain terminal. A recovered value can feed subsequent CPU or GPU work with explicit transfers.

The [shared placement frontend](../docs/design/placement-ir.md) now checks device selectors, explicit transfers and tensor residency. Inspect it with `kalandra-check --placement --dump-ir`; Metal builds also emit `placement.ir`. The current supervisor emitter still uses source syntax. Flat tensor literals can provide explicit constant shapes, such as `tensor([], [0, 3])`, through the same checked constructor rules.

The mixed CPU/GPU supervisor now lowers checked placement IR into native continuations, including resolved calls, shape checks, nested groups and error recovery. [The lowering design](../docs/design/placement-ir.md#ir-driven-supervisor-continuations) describes the typed lowering path. Both CPU tasks and the Metal supervisor now use the [common continuation planner](../docs/design/continuations.md); inspect it with `kalandra-check --dump-plan` (add `--placement` for mixed `main`).


## CPU binary64 lowering proof

The shared strict arithmetic engine now has a [CPU-only binary64 specialization](../docs/design/numbers.md#cpu-binary64-arithmetic-lowering-proof), using integer intermediates to preserve declared rounding and subnormal behavior independently of host floating controls. The optional proof configuration includes debug, optimized and ASan/UBSan APFloat conformance tests across eight ARM floating environments. Source float64/default float and typed native/worker integration are now [implemented and qualified](../docs/design/numbers.md#cpu-float64-scalar-source-and-worker-integration). Synchronous float64 tensor literals/elementwise operations are now [qualified](../docs/design/numbers.md#cpu-float64-tensor-literals-and-elementwise-arithmetic). Float64 tensor worker captures/results are now [qualified](../docs/design/numbers.md#float64-tensor-captures-and-results-in-cpu-tasks). CPU float64 reductions are now [qualified](../docs/design/numbers.md#cpu-float64-reducesum). CPU float64 matmul is now [qualified](../docs/design/numbers.md#cpu-float64-matmul). GPU float64 arithmetic remains gated; the existing binary32/Metal API retains its format restriction. The strict engine is available in the ordinary CPU build without enabling Metal.
