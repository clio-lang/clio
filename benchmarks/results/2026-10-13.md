Measured on Apple M2 Max, 12 logical CPUs, 96 GiB RAM, macOS 26.5 arm64. These are local microbenchmarks on a shared development machine, not a production performance promise.

## What this says about Kalandra

Compare generated Kalandra with handwritten JavaScript **on the same engine**:

| Workload   | Kalandra / handwritten JS on Bun | Kalandra / handwritten JS on Node |
| ---------- | -------------------------------: | --------------------------------: |
| fib        |                            0.85× |                             1.01× |
| recurrence |                            1.28× |                             1.02× |
| dot        |                            1.53× |                             1.04× |

A time ratio above 1 means Kalandra took longer. On Node, the generated loop kernels are close to the handwritten versions in this suite. On Bun, the recurrence and array reductions expose additional overhead worth investigating. The emitted tail-call loops use temporary bindings and array-destructuring assignment; that is a candidate to profile, not a demonstrated cause. The recursive function uses a different emitted function shape from the handwritten version; its faster Bun result is not a general compiler-speed advantage.

Java and Go lead this recursion-heavy workload. C/C++ and Node are tightly grouped on the sequential array kernel. Python/Ruby results here reflect scalar interpreted loops; they do not describe optimized native-extension libraries.

## Interpretation and next work

Every timed result passed its reference check. The old Clio benchmark was disqualified as a comparable baseline; its files remain untouched. See the [methodology and historical audit](../README.md) for workload definitions, compiler flags, setup, warm-up limitations and reproduction commands.

This suite is useful for identifying compiler/runtime costs, but three microbenchmarks cannot establish an overall language ranking. It excludes compilation/startup in the serial table, memory/GC accounting, I/O, distributed services and application-scale workloads. It does not test other operating systems or processors.

Next useful investigations are profiling the emitted loop shapes on Bun, adding allocation-heavy and record/serialization workloads, measuring cold CLI startup, and comparing equivalent multi-core implementations. Keep language redesign and optimization work in the post-release phase; this report does not change the revival release scope.
