# Optimized numerical API comparison

Whole dot / AXPY+sum / GEMM+sum tasks. Fresh output allocation and language dispatch included; setup/input initialization/library loading excluded. C++/Rust/Python use uninitialized fresh output where APIs permit; Go uses zero-initialized make and natural GC. Sum uses optimized BLAS dot with preinitialized ones for BLAS bindings, NumPy sum for NumPy. Shared OpenBLAS backend across C++/Go/Rust/Python/NumPy; these are API/binding comparisons, not independent language kernels. Explicit queried 1/12 OpenBLAS thread modes; Accelerate SINGLE/AUTO are queried, AUTO is not a claimed fixed thread count. Kalandra CPU is single-thread; GPU resident/transfer boundaries retained. Float64 GPU is explicitly software fallback; float32 GPU is hardware. Timed dyadic inputs require exact batch checksums. Non-dyadic verification permits justified gamma-based rounding error without changing Kalandra arithmetic semantics.

Three fresh measured processes per cell, two warmups and seven measured batches, median of process medians. Every timed/warmup checksum is independently exact; non-dyadic per-cell/scalar accuracy is checked before timing. The JSON retains all verification errors/bounds and actual thread settings.
